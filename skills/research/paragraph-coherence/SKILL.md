# Paragraphing

**Inputs:** the draft and its move map or outline.

## Planning

Before drafting, list each idea the section must cover, put them in logical order, and note what to say about each. Each idea becomes a paragraph.

## Procedure

1. Give each paragraph one main job and open with a topic sentence that tells the reader what the paragraph is about.
2. Go from general to specific. Start with the overview or the link back, then add the detail (overview before details).
3. Order sentences from known to new. Link them by repeated key terms, precise pro-forms, or genuine logical signals. See [signalling](../signalling-transitions/SKILL.md).
4. Start a new paragraph when the topic or job changes: prior work to gap, main result to exception, result to implication, one experiment to the next.
5. Merge adjacent one-sentence paragraphs that do the same job. Split paragraphs that cover more than one idea.
6. Run the skim test: read only the first sentence of each paragraph. The section's argument should stay visible. Readers use this to preview a paper.
7. Check that each "this" or "these" has a clear referent.

## Guardrails

There is no ideal sentence count. Respect journal layout and the real structure of the work. Keep separate paragraphs for separate experiments or claims.

## Check

Does each paragraph have a point a reader can state? Are clusters of tiny paragraphs or blocks of text avoided? Does the first-sentence skim give the section's logic?

**Illustrative example:** A Results paragraph opens with "Calibration reduced median error at two sites," then gives the two values, the exception, and the figure reference.
