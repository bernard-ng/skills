## What it does

Finds candidate roles from the story and themes, describes each in a sentence, and defends or discards it before any duties are assigned.

It does not turn nouns into classes. It adds invented objects for coordination, connections, and structure, and starts concrete before generalizing.

## When to reach for it

- **Invocation.** Model-invoked: the agent reaches for it when the task fits, or you can name it.
- **Trigger boundary.** Reach for this when objects or classes are unclear or a model mirrors the domain mechanically. For naming, use [name-design-objects](./name-design-objects.md); for what candidates share, use [define-shared-roles](./define-shared-roles.md).

## Common questions

**How many candidates is normal?**
Twenty to fifty for a sizable design is plausible. More appear as duties are assigned.

**Should users be objects?**
Only if who they are changes behavior. Otherwise model their actions.

## It's working if

- Every accepted role has a purpose, a client or scenario, and a difference from its neighbors.
